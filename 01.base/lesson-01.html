Курс по платформе МПК-Пересвет Урок 1 из 13

Установка платформы

Чему учимся на этом уроке
  • устанавливать платформу;
  • запускать Конфигуратор модели.
Результат урока

К концу урока платформа запущена, а в браузере открывается Конфигуратор — рабочее место, в котором строят модель.

Платформа работает в контейнерах Docker. Скрипт установки поднимает их одной командой, поэтому урок займёт несколько минут. Виртуальная машина должна быть подготовлена, как описано в разделе «Подготовка».

1

Установка

Скачайте архив peresvet-product-<версия>.tar.gz со страницы релизов и распакуйте его:

$ tar -xzf peresvet-product-<версия>.tar.gz
$ cd peresvet-product-<версия>
Откройте файл .env и впишите в PRS_IP IPv4-адрес компьютера, например PRS_IP=192.168.1.87.

Платформа открывается по HTTPS, а сертификат выпускается на адрес из PRS_IP. Без адреса скрипт не запустится. Браузер предупредит, что сертификат самоподписанный, — для учебного стенда это нормально. Открывать платформу можно двумя способами.

  • По IP. Впишите в PRS_IP адрес, по которому браузер достучится до машины с платформой (если браузер на той же машине — 127.0.0.1).
  • По имени. PRS_IP нужен и здесь. Дополнительно впишите в .env имя: PRS_HOSTNAME=plant.local, которое будете вписывать в адресной строке браузера для доступа к Конфигуратору.

Остальные настройки оставьте как есть.

Запустите платформу…

Скрипт run_one_app.sh готовит и запускает всю платформу:

  • проверяет адрес из PRS_IP и передаёт имя и адрес сервера в настройки nginx;
  • скачивает образы контейнеров, которых ещё нет на машине;
  • поднимает через docker compose контейнеры платформы: ядро, базу PostgreSQL, брокер сообщений RabbitMQ, сервер иерархической модели OpenLDAP, Grafana и вспомогательные сервисы;
  • генерирует самоподписанный сертификат для HTTPS на адрес из PRS_IP;
  • запускает nginx, который принимает все обращения по HTTPS и направляет их нужному сервису.

Первый запуск занимает несколько минут.

Запускать скрипт нужно один раз: после перезагрузки сервера контейнеры поднимутся сами, как только запустится Docker.

…с ключами для работы с ИИ:

Ключи --mcp-peresvet и --mcp-grafana дополнительно запускают два MCP-сервера. MCP — открытый протокол, по которому ИИ-ассистент (например, в Cursor) подключается к приложению и вызывает его инструменты. В следующих уроках ассистент будет помогать строить модель, поэтому серверы нужны с самого начала.

  • --mcp-peresvet true — MCP платформы: через него ассистент создаёт и читает объекты, теги, тревоги и методы модели. Адрес: https://<адрес из PRS_IP>/mcp/peresvet;
  • --mcp-grafana true — MCP Grafana: через него ассистент работает с экранами Grafana. Адрес: https://<адрес из PRS_IP>/mcp/grafana.

Без этих ключей серверы не запускаются: по умолчанию оба выключены. Подключение ассистента к ним разберём в уроке, где оно понадобится.

Команда запуска:

$ ./run_one_app.sh --mcp-peresvet true --mcp-grafana true
2

Вход в Конфигуратор

Откройте в браузере https://<адрес из PRS_IP>/grafana или, если вы задали имя хоста, https://<имя из PRS_HOSTNAME>/grafana. В примерах урока платформа установлена на 192.168.1.87, поэтому адрес — https://192.168.1.87/grafana. Браузер предупредит, что сертификат сайта не подтверждён, — для учебного стенда это нормально, продолжите вход.

Откроется страница входа.

Имя и пароль при первом входе — admin / admin. Grafana сразу предложит сменить пароль. После входа откроется Конфигуратор: слева дерево модели, справа свойства выбранного узла.

Над деревом — поле «Поиск по имени или GUID», под ним — корни модели, а внизу — «Сервисы» с журналами процессов платформы. Кнопка «…» справа от корня открывает меню команд узла.

Рядом с надписью «Пересвет» стоит шестерёнка — это настройки Конфигуратора. Нажмите её, откроется окно.

В окне три настройки:

  • Привязка тегов и тревог к хранилищу по умолчанию при создании. Если флажок включён, новый тег или новая тревога сразу привязываются к хранилищу с признаком «по умолчанию» — вам не придётся делать это вручную. Если флажок снят, узел создаётся без привязки. Тег типа «Видеопоток» к хранилищу истории не привязывается в любом случае;
  • Сортировка узлов по алфавиту. Пока флажок снят, узлы одного типа идут в том порядке, в котором их возвращает платформа. Если флажок включён, конфигуратор сортирует узлы одного типа по алфавиту. Сами типы всегда идут в одном порядке: папки, объекты, теги, тревоги, методы, коннекторы, расписания, хранилища;
  • Размер шрифта. Число в пикселях, по умолчанию 16, допустимо от 10 до 32. Меняет шрифт всей страницы Конфигуратора: дерево, подписи и поля. Подберите удобный для вашего экрана.

В «Хранилищах данных» уже есть хранилище psql — база PostgreSQL, созданная при установке. Оно понадобится в следующем уроке.

Проверка

  • Скрипт ./run_one_app.sh завершился без ошибок.
  • Конфигуратор открывается, вход выполнен.
  • В «Хранилищах данных» есть psql.

В расширенном курсе

  • из каких сервисов состоит платформа и зачем каждый нужен;
  • установка из исходного кода;
  • все настройки файла .env;
  • установка на сервер без доступа в интернет;
  • свой сертификат для HTTPS;
  • остановка и обновление платформы.

Расширенный курс готовится. Пока эти темы описаны в справочнике: «Установка и запуск».
