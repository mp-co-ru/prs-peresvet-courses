# Задание для peresvet: тревоги, видео и формы Конфигуратора

Контекст. Базовый курс (репозиторий prs-peresvet-courses, урок 5 «Тревога по уровню» и урок 9 «Сводный экран») опирается на тревоги платформы. На стенде v0.26.3 (192.168.1.87) тревога срабатывает, но остальное не работает. Нужно починить серверную часть и форму тревоги в Конфигураторе так, чтобы сценарий из раздела «Как должно работать» проходил целиком. Кодовая база: `src/services/alerts/`, `src/services/dataStorages/`, `src/grafana/configurator/Configurator.json`.

## Что сломано (проверено на стенде 2026-11-16)

1. **Пропадание и квитирование не пишутся в хранилище.** `alerts_app` публикует `prsAlert.app.alarm_on|alarm_off|alarm_acked.<id>` с телом `{"alertId": ..., "x": ...}`, а обработчики `dataStorages` (`_alarm_off`, `_alarm_ack`, базовый класс и `dataStorages_app_postgresql_svc.py`) ждут `{"data": {"alertId": ..., "x": ...}}`. В журнале: `dataStorages_app_postgresql :: Ошибка обработки сообщения {'alertId': '…', 'x': …} с ключом prsAlert.app.alarm_off.…: 'data'`. В таблице тревоги `a_<id>` (колонки `x`, `cx`, `e`) заполняется только `x`. Привести формат к одному виду, проверить все три события.
2. **Квитирование `PUT /v1/alarms/`** отвечает 200, но ничего не делает: в `alerts_app_svc._ack_alarm` читается `mes["data"]["x"]`, которого нет. Кроме того, `x` по умолчанию `None` (валидатор `AckAlarm.x` на значении по умолчанию не срабатывает) — тогда в кэш пишется `acked = None`. Нужно: если `x` не передан, брать текущий момент.
3. **`GET /v1/alarms/` всегда 500**: RPC `prsAlert.app_api.get_alarms` возвращает `None`, дальше `alerts_app_api_svc.alarms_get` падает на `res["data"]` (`TypeError: 'NoneType' object is not subscriptable`) и FastAPI — на валидации ответа. Разобраться, почему `alerts_app._get_alarms` не отвечает (поиск по `base` списком? исключение внутри?). Там же: `"id": alert` кладёт кортеж целиком вместо `alert[0]`; ветка `format` в `alarms_get` переводит ключ `fired`, а элементы содержат `start`.
4. **После пропадания тревога забывается сразу** (`_tag_value_changed` обнуляет `fired` и `acked` при `alarm_off`), поэтому неквитированная, но уже пропавшая тревога не попадает в список, хотя докстринг `AlarmsGet` обещает «активные, либо неактивные и неквитированные».
5. **`GET /v1/data/?tagId=<id тревоги>`** — 500 `int() argument must be … not 'NoneType'` (tags_app). Либо отдавать историю событий тревоги, либо отвечать понятной ошибкой 4xx.
6. **Форма тревоги в Конфигураторе** (`#div-alertConfig`): поля «Сравнение», «Значение», «Автоквитирование» лежат в колонках `col-1`, поэтому сжаты до ~40 px, подписи наезжают друг на друга, значения в списках не видны. Сделать нормальную ширину (как у остальных полей формы).

Попутно найдено, не про тревоги:

7. Конфигуратор: после удаления дочернего метода тег остаётся оранжевым, а в списке «!» висит «В ветке есть вычислительный метод без инициатора» — до перезагрузки страницы.
8. Grafana: источник `peresvet` провижится с `url: http://NGINX_HOST/v1/` (`config/grafana/provisioning/datasources/prs.yaml`), а nginx на 80-м порту отвечает `301` на HTTPS, поэтому прокси Grafana не получает данных. Нужен `https://…/v1/` с `tlsSkipVerify: true` (или внутренний адрес без редиректа).
9. **Видео не работает с камерой HEVC (192.168.1.72, `live/ch00_0`, 2304×2592, `yuv420p`, `color_range=tv`).** В `src/services/video/camera.py`, `session_ffmpeg_args`, выход `preview.jpg` кодируется в MJPEG без `-pix_fmt yuvj420p`; ffmpeg 7.1 отказывается («Non full-range YUV is non-standard… ff_frame_thread_encoder_init failed»), и падает весь процесс захвата: «поток прервался, перезапуск» каждые 3 с, файлы архива по 0 байт, живого потока и снимков нет. В `snapshot_file_args` это уже учтено — сделать так же (или `format=yuvj420p` в `_PREVIEW_VF`). Там же сегментер архива с `-c:v copy` пишет «[mpegts] first pts and dts value must be set … Error muxing a packet» — проверить после первого исправления, при необходимости добавить `-fflags +genpts` или аналог. Эта же камера указана примером в `docs/source/video.rst`.
10. **Новое хранилище, созданное в Конфигураторе, нельзя настроить.** Команда «Новое хранилище» создаёт узел с типом `0` и пустой конфигурацией; `dataStorages_app_postgresql` тут же начинает бесконечно переподключаться («Ошибка связи с базой данных '<id>': the JSON object must be str, bytes or bytearray, not NoneType» дважды в секунду), а `PUT /v1/dataStorages/` для этого узла зависает без ответа — ни имя, ни тип `3`, ни конфигурацию записать нельзя. После `DELETE` хранилища попытки подключения продолжаются до перезапуска сервиса. Через API хранилище видео создаётся нормально, если сразу передать `prsEntityTypeCode: 3` и конфигурацию.
11. **Формы расписания и тревоги** — те же колонки `col-1`/`col-2`: у расписания поля «Начало» и «Окончание» обрезаны до «16.11» и «dd.m», подписи «Периодичность»/«Длина периода» наезжают друг на друга. Заодно: «Начало» нового расписания по умолчанию — момент запуска сервиса (значение по умолчанию в `ScheduleCreateAttributes` вычисляется при импорте модуля), а не момент создания.
12. **Заголовок свойств**: подписи «Коннектор:», «Расписание:», «Хранилище данных:» не помещаются в колонку и обрезаются или переносятся под кнопку копирования.
13. **Grafana и JSON API.** «Сохранить и протестировать» у источника с адресом `https://<сервер>/v1/` отвечает «JSON API: Not Found»: проверка запрашивает корень `/v1/`, а там 404 (отвечает только `/v1/version`). Стоит отдавать 200 по `GET /v1/`. В `docs/source/grafana/grafana_integration.rst` путь запроса указан как `data/`, а плагин 1.3.24 склеивает его с адресом прокси без слэша (`…/proxy/uid/<uid>data/` → «Unable to find datasource») — нужно `/data/`. Там же стоит упомянуть Cache Time: по умолчанию 5 минут, для живых экранов — `0s`.

## Как должно работать (на это опираются уроки)

Тревога «Высокий уровень» на теге «Уровень»: `{"high": true, "value": 90, "autoAck": false}`, привязана к хранилищу `psql`.

1. В «Уровень» записали 95 → тревога активна. В `a_<id>` строка с `x` = метка значения 95.
2. `GET /v1/alarms/?parentId=<id объекта «Насос»>&getChildren=true&format=true` →
   ```json
   {"data": [{"id": "<id тревоги>", "cn": "Высокий уровень", "description": "",
              "tagId": "<id тега «Уровень»>",
              "fired": "2026-11-16T16:25:32.429572+03:00", "finish": null, "acked": null}]}
   ```
   Без `format` метки — целые микросекунды. `parentId` можно не передавать — тогда тревоги всей модели (нужно для панели Grafana).
3. `PUT /v1/alarms/` с телом `{"id": "<id тревоги>"}` → 200; в ответе на п. 2 `acked` заполнено; в `a_<id>` заполнено `cx`. Повторное квитирование — без изменений, без ошибок.
4. В «Уровень» записали 80 → тревога пропала: `e` в `a_<id>` заполнено; в `GET /v1/alarms/` (по умолчанию `fired=true`) её больше нет.
5. Если тревога пропала, не будучи квитированной, она видна в `GET /v1/alarms/?fired=false` с заполненным `finish` до квитирования; после квитирования исчезает.
6. При `autoAck: true` квитирование записывается в момент срабатывания (`acked == fired`).
7. Состояние тревог переживает перезапуск сервиса (кэш восстанавливается из таблицы тревоги, а не только из последнего значения тега).

Для урока 8 (камера): коннектор «Камера помещения» с `{"source": {"rtspUrl": "rtsp://192.168.1.72:554/live/ch00_0", "rtspTransport": "tcp"}}`, хранилище «Видеоархив» (тип 3, `{"archivePath": "/var/lib/peresvet/video", "retentionHours": 24}`), тег «Камера» типа «Видеопоток» в объекте «Помещение». Должны работать: зелёный кружок у коннектора, живой поток на вкладке «Хранилище» тега, снимок `GET /v1/data/?tagId=<id>&finish=<момент>` (`image/jpeg`), запись за период с `start` и `finish` (`video/mp4`).

Готово, когда: сценарий 1–6 проходит на стенде запросами `curl`; есть тесты на формат сообщений `alarm_on/off/acked` между `alerts_app` и `dataStorages` и на `GET/PUT /v1/alarms/`; форма тревоги в Конфигураторе выглядит как остальные формы; документация `docs/source/alerts.rst` описывает `GET/PUT /v1/alarms/` с примерами.
